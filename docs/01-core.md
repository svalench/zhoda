# Слой 1: zhoda-core — движок дельберации

> Python / FastAPI. Независимое ядро: не знает ни про dsh, ни про MCP.
> Вход — вопрос пользователя, выход — вердикт + minority report + хроніка.
> Статус: рабочий MVP-цикл реализован (см. §10).

## 1.5. Стадия -1 — протокол-роутер

Дебаты — не универсальное улучшение: для простых фактических задач голосование
(self-consistency) дешевле при том же качестве. Поэтому на входе классификатор
выбирает протокол:

| Класс задачи | Протокол | Почему |
|---|---|---|
| `factual_lookup` | `vote` (N ответов + majority) | Дёшево, дебаты не добавляют |
| `reasoning` | `debate` | Раунды критики поднимают точность |
| `decision` | `debate` + элиситация | Ответ зависит от недосказанных ценностей |
| `code_review` | `red_team` | Адversarial-поиск дыр |
| `creative` | `vote` + председатель | Консенсус не нужен |

Целевой класс Zhoda — `decision`: архитектурные вердикты, выбор технологий,
ревью планов. Там дебаты сильнее голосования, и там живёт наша аудитория.

**Уверенность роутера — межмодельная, не самооценка** (раунд 3, §4): задачу
классифицируют ДВЕ разные модели из явного конфига (`router_classifiers`);
согласие = confidence 1.0, разногласие = эскалация вверх (дебаты), task_class
честно берётся из более thorough класса. Ограничение (раунд 4, §3): согласие
двух классификаторов ≠ корректность — модели одного семейства ошибаются
согласованно; fail-safe ловит разногласие, но не общий bias.

## 2. Стадия 0 — элиситация (smart по умолчанию)

Проблема, которую закрываем: LLM фабрикуют ответ вместо уточняющего вопроса.
Но и пользователи не любят анкету перед ответом — поэтому:

1. Все модели совета получают сырой запрос и возвращают **не ответ**, а список
   неясностей: `{ambiguity, why_it_matters, candidate_question, options[]}`
2. Ambiguity-score — межмодельный: доля моделей, независимо поднявших
   неясности (не самооценка!). Вопросы — ТОЛЬКО если score ≥ порога (0.6),
   максимум 3, с вариантами ответов (one-tap)
3. Если score ниже порога — совет отвечает сразу, а допущения помечаются
   в вердикте (`assumptions[]`)
4. Дебаты могут приостановиться и запросить уточнение посреди спора

```python
class ValueMap(BaseModel):
    goal: str                    # зачем: какое решение примут по ответу
    success_criteria: list[str]  # критерии хорошего ответа
    constraints: list[str]       # бюджет, сроки, стек, запреты
    anti_goals: list[str]        # что точно НЕ нужно
    assumptions: list[str]       # допущения, принятые без вопросов (smart-режим)
    open_ambiguities: list[str]  # оставшиеся неясности (для minority report)
```

Режимы: `smart` (дефолт), `--no-clarify`, `--auto-clarify`.

## 3. Стадии 1–2 — позиции и фракции

Каждая модель отвечает структурированно:

```python
class Position(BaseModel):
    thesis: str                  # суть позиции в 1–2 предложениях
    answer: str                  # полный ответ
    arguments: list[str]         # ключевые аргументы
    falsifiability: str          # при каких условиях позиция неверна
    confidence: float            # 0..1
```

Кластеризация во фракции (снизу, не назначение ролей — защита от искусственной
поляризации):

1. Попарное структурное сравнение судьёй: «это одна позиция? если нет — в чём
   расхождение»; union-find по «same»; расхождения сразу сидят dissent_map
   (эмбеддинги отложены: в MVP-срезе судья дешевле и точнее, см. раунд 3 §3)
2. Фракция из 2+ моделей вырабатывает платформенный ответ (внутренний раунд);
   одиночки — «независимые»
3. Фракции получают имена от председателя: «Прагматыкі», «Максімалісты»...

## 4. Стадия 3 — дебаты (оксфордский формат, анти-капитуляция)

Один раунд:

1. Каждая фракция выдвигает критику против сильнейшей ДРУГОЙ фракции
   (лидирующая атакует вторую — ротирующий devil's advocate)
2. Целевая фракция отвечает ребутталом
3. Судья решает, закрыта ли претензия (аудируемая точка доверия, логируется)
4. Переход фракции — ТОЛЬКО при обеих половинах (раунд 4, §6): открытая
   претензия по `objection_id` против текущей фракции модели И непустая
   цитата `convinced_by`. Закрытие претензии — только ребутталом ОТ целевой
   фракции (раунд 4, §5)

```python
class Critique(BaseModel):
    id: str                      # присваивается движком при регистрации
    target_faction: str
    flaw_type: Literal["factual", "logical", "scope", "values_mismatch"]
    claim: str                   # конкретное утверждение, с которым спорим
    specifics: str               # обязательно для scope/values_mismatch
    rebuttal: str
    status: Literal["open", "closed"]

class FactionSwitch(BaseModel):
    model: str
    from_faction: str
    to_faction: str
    convinced_by: str            # цитата убедившего аргумента (обязательна)
    objection_id: str            # открытая претензия, по которой перешли
```

## 5. Стадия 4 — згода и остановка

- Схождение считается по тезисам через судью (`all_agree`), НЕ по похожести текстов
- **Stability-правило**: згода считается достигнутой, если согласие
  продержалось 2 раунда подряд — защита от случайного флипа большинства
- Адаптивная остановка: стабильная згода → стоп; иначе кап раундов (default 4)
- Сила консенсуса: `unanimous` / `majority` (≥2/3) / `split` / `deadlock`
- При `split/deadlock` и включённой эскалации — апелляция на ступень выше
  по лестнице моделей; председатель выносит решение по хроніце

## 6. Стадия 5 — вердикт

```python
class Verdict(BaseModel):
    decision: str                # ответ большинства
    zhoda_reached: bool          # достигнута ли згода (со stability)
    consensus_strength: Literal["unanimous", "majority", "split", "deadlock"]
    protocol: Literal["vote", "debate", "red_team"]   # что выбрал роутер
    router_confidence: float     # согласие двух классификаторов (1.0/0.0)
    value_map: ValueMap          # против чего проверялось (+ assumptions)
    minority_report: str | None  # позиция меньшинства — сохраняется!
    dissent_map: list[Disagreement]   # где и почему разошлись
    switches: list[FactionSwitch]     # кто и почему изменил позицию
    rounds_taken: int
    cost: CostReport             # запросы, токены, кэш-хиты, latency
    transcript_id: str           # ссылка на полную хроніку
```

## 7. Репутация (после MVP)

- ELO-рейтинг моделей по доменам задач: чья критика принята (+), чьи ошибки
  подтвердились (−), чьи переходы оказались к лучшему (+)
- **Анти-капитуляция**: переход, после которого новая позиция оказалась
  ошибочной, штрафует сильнее, чем ошибочная, но удержанная позиция
- **Честно про ground truth** (раунд 3, §4): до слоя отложенной верификации
  (opt-in фидбек «вердикт сработал?») репутация измеряет риторическую
  устойчивость, а не истинность — и называется соответственно
- Влияет на: состав совета под задачу, вес голоса при консенсусе
- Хранилище: SQLite (локально) / PostgreSQL (сервер)

## 7.5. Три точки доверия (честность протокола)

Zhoda не устраняет доверие к моделям — она концентрирует его в трёх
аудируемых точках (раунд 3, §6):

1. Классификация роутера (две модели, согласие логируется)
2. Закрытие возражений (семантическое «ответил ли ребуттал» — судья)
3. Попарное сравнение позиций при кластеризации фракций (судья)

Каждая точка — отдельный логируемый вызов в хроніце. Это не фатально:
структура протокола проверяема, а точки доверия — аудируемы.

## 8. Технические решения

- **Стек:** Python 3.12+, FastAPI, async httpx, Pydantic v2, uv
- **Параллелизм:** `asyncio.gather(return_exceptions=True)` — graceful
  degradation: упавшая модель исключается из раунда, ошибка только если упали все
- **Провайдер:** семафор конкурентности, Retry-After + бэкофф на 429,
  различение rate limit / quota, парсинг usage, фейл-fast на 4xx,
  per-question бюджет (begin_question + дельта) с pre-call оценкой
- **Кэш:** семантический кэш на уровне стадий (позиции кэшируются по
  hash(question + value_map + model)); переиспользовать llm-cache-router
- **Хранение хронік:** JSONL через TranscriptStore (core/src/zhoda_core/transcripts.py)
- **Анонимизация:** алиасы на КАЖДУЮ дельберацию (не на движок), метки
  A..Z, AA.. — советы >26 моделей не ломают
- **Конфиг совета:** YAML — состав, лестница эскалации, кап раундов, пороги

```yaml
# zhoda.yaml — пример
council:
  - deepseek/deepseek-chat-v3:free
  - google/gemma-3-27b:free
  - qwen/qwen3-32b:free
  - meta-llama/llama-4-scout:free
chairman: google/gemini-3-pro        # судья и апелляции
router_classifiers:                  # явно, НЕ из порядка совета (раунд 4 §3)
  - deepseek/deepseek-chat-v3:free
  - google/gemma-3-27b:free
rounds_cap: 4
ambiguity_threshold: 0.6             # smart-элиситация, TODO(calibrate)
devils_advocate: true
stability_rounds: 2                  # згода должна продержаться
escalation:
  enabled: false                      # true = платная апелляция
  ladder: [free, mid, frontier]
budget_per_question_usd: 0.0          # жёсткий предел расхода НА ВОПРОС
```

## 9. API ядра (черновик)

```
POST /v1/clarify          → вопросы к пользователю | ValueMap (smart)
POST /v1/deliberate       → полный цикл → Verdict (SSE-стрим стадий)
GET  /v1/transcript/{id}  → полная хроніка дебатов
GET  /v1/reputation       → рейтинг моделей по доменам
GET  /v1/health
```
