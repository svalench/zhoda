# Zhoda — мастер-план проекта

> **Zhoda** (ад белarusk. «згода» — согласие, консенсус) — открытый движок машинной
> дельберации: модели сначала расспрашивают вас о цели, потом делятся на фракции
> и спорят, как люди, — пока не дойдут до згоды. Вы получаете вердикт большинства,
> minority report и полный транскрипт пути к истине.
>
> *Models argue until they reach zhoda.*

## 1. Суть

Zhoda — open-source система, в которой несколько LLM решают задачу не параллельными
ответами (как llm-council Карпаты) и не голосованием (как conclave), а
**структурированным спором фракций** с предварительным уточнением ценности запроса.
Киллер-кейс: вердикты по архитектурным решениям в коде (см. §10).

Три принципа:

1. **Сначала понять, потом решать.** Совет не отвечает на сырой промпт — он
   интервьюирует пользователя и строит карту ценности (цель, критерии успеха,
   ограничения, анти-цели).
2. **Спорить фракциями, как люди.** Модели объединяются вокруг позиций, ведут
   межфракционные дебаты, могут публично переходить в другую фракцию под силой
   аргумента.
3. **Згода или честный раскол.** Если консенсус не достигнут — вы получаете не
   фальшивое согласие, а карту разногласий: *zhoda or honest dissent*.

## 3. Почему сейчас и почему мы

- Ниша пуста: на GitHub нет инструмента «уточнение → фракции → дебаты → вердикт»
  (проверено 23.08.2026: llm-council — один проход без ревизий; conclave —
  голосование; dsh-экосистема — ноль council/debate-плагинов).
- DeepSeek Harness (dsh) открыт 13.08.2026 под MIT, 186k★ за 10 дней, экосистема
  плагинов в стадии land-grab — окно раннего входа.
- Академическая база: multi-agent debate сходится к более точным ответам
  (Du et al.), адаптивная остановка — 4–8 раундов, чаще 5–6; дебаты vs голосование
  зависит от задачи (NeurIPS 2025, debate-or-vote) — поэтому в ядре
  протокол-роутер (docs/01-core.md §1.5).

## 4. Архитектура: три слоя

```
┌─────────────────────────────────────────────────────┐
│  Слой 3: @zhoda/dsh-plugin (TypeScript)             │
│  Нативный плагин DeepSeek Harness: UI дебатов,      │
│  граф фракций, панель вердикта. Витрина проекта.    │
├─────────────────────────────────────────────────────┤
│  Слой 2: zhoda-mcp (Python)                         │
│  MCP-сервер: zhoda_clarify / _deliberate /          │
│  _verdict / _transcript / _reputation. Работает в   │
│  dsh, Claude Code, Codex и любой MCP-обвязке.       │
├─────────────────────────────────────────────────────┤
│  Слой 1: zhoda-core (Python / FastAPI)              │
│  Движок дельберации: роутер, элиситация, фракции,   │
│  раунды, консенсус, вердикт, репутация.             │
└─────────────────────────────────────────────────────┘
```

Правило зависимостей: верхние слои зависят от нижних, нижние — ни от кого.
Поломка preview-API dsh затрагивает только слой 3.
Порядок сборки: core → mcp → plugin (MCP даёт интеграцию с dsh бесплатно,
т.к. dsh поддерживает MCP-серверы; плагин — чистая витрина).

## 5. Провайдеры моделей

- Первый класс — OpenRouter: 25+ бесплатных `:free`-моделей (20 req/min,
  50 req/day без кредитов, 1000 req/day после разового $10).
- BYOK: пользователь приносит свой ключ — инфраструктурная себестоимость ноль.
  Стоимость токенов и время честно показываются ДО запуска (estimate);
  latency — часть продукта: «инструмент второго мнения», не мгновенный чат.
- Лестница эскалации: бесплатные модели = первая инстанция; при слабом консенсусе
  дело уходит в «апелляцию» к платным моделям (опционально, по конфигу).
- Кэширование ответов (переиспользуем наработки llm-cache-router) растягивает квоты.
- Честно о слабом звене: 5 раундов слабых моделей могут уверенно сойтись
  неправильно — поэтому бенчмарк в составе MVP (§7), а не после.

## 6. Монетизация и лицензии

- Сплит-лицензии: движок `zhoda_core`, `zhoda-mcp`, плагины — **Apache-2.0**
  (максимум интеграций); API-сервер (`api/`) — **AGPL-3.0** (защита от
  облачных клонов). Моат — репутационные данные, бренд, комьюнити.
- Донаты: GitHub Sponsors (0% комиссии для физлиц) + OpenCollective (прозрачная
  смета) + крипто-адрес в README.
- Честно про донаты: это покрытие хостинга и API-кредитов, не зарплата.
  Стратегический дивиденд — репутация, звёзды, публикации (досье для O-1).
- Далёкий опцион: hosted-версия за подписку (loose open core) — только после traction.

## 9. Чего не делаем (явно)

- Не форкаем dsh (453K строк preview-кода с breaking changes — ад поддержки)
- Не запускаем токен до реального спроса (если вообще запускаем)
- Не строим бизнес на фарме бесплатных тиров OpenRouter (нарушение ToS)
- Не делаем «ещё один чат с несколькими моделями» — наша ценность в протоколе
- Не обещаем в документах цифры, которые не измерены

## 10. Киллер-кейс и первые 100 пользователей

- **Киллер-кейс**: вердикты по архитектурным решениям в коде — ADR-ревью,
  «рефакторить X или Y», выбор библиотеки. Ответ зависит от недосказанных
  ограничений (стадия 0 блистает), качество измеримо рубриками, аудитория
  уже живёт в dsh/Claude Code.
- **Первые 100 пользователей**: dogfooding в своих проектах → MCP-реестры →
  awesome-dsh-plugin → статья с цифрами бенчмарка («+X% против однопроходного
  совета») на Dev.to и r/LocalLLaMA. Бенчмарк — это и есть контент дистрибуции.
