# Как работает протокол (2026-09-05)

Срез после двух живых пачек `core/eval/questions.jsonl` и правок честности.
Цифры: [утро, `--no-clarify`, cap 6](2026-09-05-eval-batch.md) и
[вечер, `--auto-clarify`, cap 4](2026-09-05-eval-cap.md). Хронікі рядом.
Схема: [docs/01-core.md](../01-core.md).

## Зачем меняли

Утром совет выдавал **згоду без единогласия**: majority на капе + hybrid
«Kafka alongside PostgreSQL» / «it depends». Это ложь протокола — majority
не есть згода. Второй прогон проверил, что раскол стал честным.

## Как оно едет

1. **Роутер** (два классификатора) → `vote` / `debate` / `red_team`.
   Несогласие классификаторов → debate.
2. **Stage 0.** `smart` спрашивает. `auto-clarify` не спрашивает: неспрошенное
   → `open_ambiguities`, не в assumptions. `no-clarify` пропускает LLM.
   Если вопроса «evaluate/review project X» и нет `--context` — сразу
   `insufficient_context`, **без** Stage 0 LLM (`auto-clarify` / `no-clarify`).
   `red_team` с `--context`: исходник и есть объект, Stage 0 не зовётся.
3. **Позиции → фракции.** Критики анонимны. Синтетическая оппозиция
   (devil's advocate при единогласии) подписана в minority.
4. **Раунды** до `rounds_cap` (дефолт 4). Early-stop только после
   `stability_rounds` **unanimous** (`all_agree` на primary rec вопроса,
   не на общих caveats). Majority голову не останавливает.
5. **На капе.** Unanimous (даже streak 1) → згода. Majority →
   `decision_origin=majority_at_cap`, `zhoda_reached=false`, карта тезисов,
   **без** плана. Split → deadlock. Апелляция — opt-in, лейбл
   `appeal_without_consensus`, не згода.
6. **Вердикт.** На згоде председатель синтезирует `decision`. Hedge
   («it depends») и hybrid на XOR-вопросе откатываются на thesis победителя.
   Если председатель стёр named claims (SQL injection) — они дописываются
   блоком `Findings:`. SUPERSEDED ≠ CLOSED. Minority не стирается.
   План-контракт только при згоде.

Vote и red_team по-прежнему считают majority згодой: это однопроходные
протоколы, не оксфордский цикл.

## Что показали живые прогоны

Один совет (gpt-4.1-mini / gemini-2.5-flash-lite / deepseek-v4-flash),
судьи gpt-4o-mini + gemini-3.1-flash-lite. Девять вопросов + kafka ×2.

| | утро | вечер |
|---|---|---|
| режим | `--no-clarify`, cap 6 | `--auto-clarify`, cap 4 |
| spend | $0.081 / 439 req / ~18 мин | $0.127 / 476 req / ~25 мин |
| роутер | 10/10 | 10/10 |
| zhoda (без IC) | 9/9 | **5/9** |
| switches | 0 | 1 (REST, слабая цитата) |
| kafka | hedge-згода / противоречивый повтор | p1 PostgreSQL (згода), p2 majority-at-cap |
| login `decision` | SQLi после фикса SUPERSEDED | «inherently insecure» (находка в позициях) |
| IC | 2 req, 2 с | 6 req, 204 с (elicit до гейта) |

Вечерний 5/9 — не регресс качества, а отказ называть majority згодой.
Четыре «нет»: monolith, kafka p2, REST, CI — все `majority_at_cap`,
карта тезисов, без плана.

Повторяемость слабая: тот же kafka, свежий кэш, p1 ≠ p2. Дебат не
кэшируется (случайные алиасы). `repeat=2` не replay.

## Что работает

- Роутер и IC-гейт не путают классы и не судят пустой объект.
- Vote: NULL ≠ TRUE, HTTP 201.
- XOR: единогласие на капе даёт один pick (PostgreSQL), не hybrid-згоду.
- Majority на капе — честный раскол, не план.
- Strangler: wrap PHP behind API, згода, план.
- Synthetic opposition подписана, не маскируется под живую фракцию.
- SUPERSEDED не прячет SQLi в «Closed objections» (хроніка `9f7795516da1`).

## Что ещё не работает как обещано

- **Спора почти нет.** Switch ≈ 0. Возражения закрываются rebuttal’ами,
  модели не переходят. Оксфорд на бумаге, на деле параллельные эссе + судьи.
- **Login во втором прогоне:** позиции видели f-string SQLi, `decision` —
  общая фраза. Auto-clarify спросил «а вдруг `db.execute` санитизит?» и
  запрет утверждать unresolved смыл находку. В коде после пачки: skip
  Stage 0 на red_team+context и `Findings:`, **живым не гоняли**.
- **IC во втором прогоне** жег Stage 0 до гейта (~3 мин). Skip без объекта
  тоже только в коде после пачки.
- **Кэш дебата мёртв** — повтор вопроса не воспроизводит исход.

## Оценки слоя

| слой | балл | комментарий |
|---|---|---|
| роутер / IC | 8.5 | классы и гейт держатся |
| vote | 8 | факты ок |
| red_team | 6.5 | видит баг, `decision` может проглотить |
| смысл дебата | 5 | згода/раскол есть, убеждения нет |
| switch | 3 | живой раз в десять прогонов |
| стабильность | 4 | один вопрос → два исхода |
| vs один чат | 5 | dissent полезен; «совет решил» рано продавать |

Протокол научился **не врать, что есть згода**. Он ещё не научился
менять мнение моделей аргументом. Пока switches ≈ 0, выход — либо
единогласие на капе, либо честный раскол. Это лучше фейкового hybrid,
хуже обещанного «модели спорят, пока не сойдутся».
